DataForge CSV → data\*.js converter · v1.0.0 · offline, nothing leaves this page

1Entity and reference data

Pick the entity this CSV feeds. Then (recommended) load your CURRENT data\*.js files as reference sets so cross-references (RAU ids, event ids, control ids) can be validated. Files convert one at a time; converted output joins the reference sets automatically, so a natural order is: orgnodes, services, riskevents, mcrs, raus, register, ratings, controls, controllinks, expectedcontrols, affirmations, challenges.

2Load the CSV

Pick the export (Excel: File > Save As > CSV UTF-8), or paste CSV text. The first row must be column headers. Quoted cells, commas and line breaks inside quotes, and a UTF-8 BOM are handled.

3Map your columns to the schema

Every schema field needs a source: one of your columns, a constant typed in, or - for optional fields - skip. Auto-matching has taken a first pass; fix anything it guessed wrong. * marks required fields.

4Map your vocabulary

These fields allow fixed values only. Your data uses words the schema does not know; map each to an allowed value (or fix the source and reload).

5Masking

Person-name fields are replaced with stable pseudonyms (Owner 001, Assessor 014, ...) before export - the same source name always gets the same pseudonym within a field, so patterns survive but identities do not. Uncheck to keep a field as-is (WORKSHEET.md W6).

6Validate

Checks: required fields, id format and duplicates, allowed values, numbers and ranges, dates, duplicate keys, and dangling cross-references against the loaded reference sets. Errors block export; warnings do not. This is the only gate - the app itself assumes clean data.

7Export

Downloads data\?.js in the exact shipped format, plus a conversion log for logs\. Back up the old file, drop this one into demo\data\, refresh the app, open Preflight, spot-check one record.

Not handled here

rubric.js and metaquestions.js usually keep the shipped versions until real standards land (metaQuestions CAN be imported above if yours exist). release.js is hand-edited at release time (runbook Part 6). RAU process maps, survey answers, and handoffs are built inside the app (map builder / survey), not imported: converted RAUs start with none. register / ratings / controls / links / affirmations / challenges are history - import them if you have it; otherwise ship them with rows: [] and let the tool fill them live.
